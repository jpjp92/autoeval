### backend 작업

- Python 3.12. `requires-python >=3.12`와 Docker 이미지 기준에 맞춘다.
- `astral-sh/setup-uv`로 설치하고 `uv sync --frozen`을 실행한다. `uv.lock`을 기준으로 한다.
- 테스트:

  ```bash
  uv run python -m unittest \
    backend.tests.test_spreadsheet backend.tests.test_table_chunking \
    backend.tests.test_english_chunking backend.tests.test_judge_content \
    backend.tests.test_eval_v2 backend.tests.test_job_ids
  ```

- 테스트 범위: 언어 판별, 영문 처리, 표 처리(펼치기·분할·중첩), xlsx·csv, Judge 응답 파싱, 평가 v2(검증·점수·파이프라인). LLM 호출은 mock이다.

- 작업 디렉터리는 `frontend/`다.

## 3. 구현 전 확인

- **Secrets 없는 환경에서 import:** 백엔드 테스트는 `.env` 없이도 import와 실행이 되어야 한다.
  - 현재 "Supabase credentials not found" 경고가 나온다.
  - `.env`가 없는 깨끗한 작업 트리에서 직접 확인한다.
- **환경변수 없는 빌드:** 프론트 `next build`도 환경변수 없이 통과해야 한다. 깨끗한 작업 트리에서 `npm ci`부터 확인한다.

## 6. 2단계: dev → main 자동 PR (2026-11-17)

파일: `.github/workflows/auto-pr.yml`

- **트리거:** `dev` push, 수동 실행. 연속 push는 마지막 실행만 남긴다(`concurrency`).
- **동작:**
  - dev가 main보다 앞서 있지 않으면 아무것도 하지 않는다.
  - 열린 dev → main PR이 없으면 새로 만든다. 있으면 본문만 갱신한다.
  - 본문에는 main 이후 커밋 목록(최대 200개)이 들어간다.
  - 병합은 사용자가 직접 한다.
- **권한:** `contents: read`, `pull-requests: write`. 토큰은 `GITHUB_TOKEN`을 쓴다.
- **필요한 저장소 설정 (사용자):** Settings → Actions → General → Workflow permissions → "Allow GitHub Actions to create and approve pull requests"를 켠다. 꺼져 있으면 PR을 만들 때 권한 오류가 난다.
- **제약:**
  - GitHub 정책상 `GITHUB_TOKEN`으로 만든 PR에는 `pull_request` 트리거 워크플로(CI)가 돌지 않는다.
  - CI는 dev push 때 같은 커밋으로 돌므로 검사 자체는 빠지지 않는다. 다만 PR 화면에 검사 결과가 붙지 않는다.
  - main 브랜치 보호에서 필수 검사를 켜려면 PAT(Secrets)로 바꿔야 한다.
- **검증:** 로컬에서는 YAML 문법만 확인했다. 실제 동작은 push 후 Actions 탭에서 확인한다(사용자).
