## 1. 원칙

- **언어 세 가지를 분리한다.**
  - 원본 문서 언어(`source_language`)는 자동 판별한다.
  - 카테고리 언어의 기본값은 `ko`다.
  - QA 출력 언어는 기존 `lang` 값을 쓰고 기본값은 `ko`다.
  - 예: 영어 논문은 영어 청크로 보존하고, 카테고리와 QA만 한국어로 만든다.
- **원문은 번역하지 않는다.** 청킹 단계에서 허용하는 변형은 PDF 추출 노이즈 교정뿐이다.
- **한국어 회귀를 막는다.** `ko` 문서는 지금의 규칙과 프롬프트를 그대로 타고, 결과가 달라지면 안 된다.
- **언어별 처리는 정책으로 나눈다.** 별도 서비스를 두지 않고, 기존 파이프라인 안에서 프롬프트와 규칙을 고른다.
- **API·DB 스키마, 임베딩 모델(Gemini Embedding 2, 1536차원)은 그대로 둔다.**
  - 언어 정보는 청크 metadata(JSON)에만 기록한다.
  - 기존 데이터는 자동으로 재청킹하거나 삭제하지 않는다.

## 3. 단계별 작업

### 1차 (P0): 영문 원문 보존

**E1. 언어 판별**
- `ingestion/language.py`의 `detect_language(blocks)`는 `{"language": "ko" | "en", "hangul_ratio": float}`를 돌려준다.
- 숫자와 기호를 뺀 글자 중 한글 비율로 판정한다. 기준값은 실측으로 정한다(예: 10% 미만이면 `en`).
- 신뢰도 값은 지어내지 않고 측정한 비율을 그대로 기록한다.
- 혼합 문서는 1차에서 `ko`로 처리한다. 현행과 같다.
- 판별 결과는 파서 직후 한 번만 정하고, 청크 metadata의 `source_language`에 넣는다.

**E2. 영문 LLM 청킹 프롬프트**
- `SYSTEM_PROMPT_EN`과 `DOCX_SYSTEM_PROMPT_EN`을 추가하고 `source_language`로 고른다.
- 공통 제약은 "Do not translate. Preserve the source language, numbers, units, citations, named entities."다.
- 영문 규칙:
  - 문단, 문장, 주제 경계로 나눈다.
  - `However`, `Therefore`처럼 연결어로 끝나는 청크를 만들지 않는다.
  - 표는 원문 언어로 산문화하되 행과 열의 관계를 보존한다.
  - `section_title`은 원문 언어로 쓴다.
- 청크 크기는 처음에는 기존 200~800자를 유지한다. 번역 문제를 고친 뒤 다시 재고, 필요하면 2차에서 언어별로 나눈다.
- 한국어 프롬프트에는 "원문 언어 유지(영문 용어·인용 번역 금지)" 한 줄만 추가한다. 나머지는 바꾸지 않는다.

**E3. LLM 출력 사후 검증**
- 원문 블록이 `en`인데 출력에 한글이 섞여 있으면 번역으로 보고 해당 배치를 한 번 다시 요청한다. 그래도 실패하면 폴백 청크를 쓴다.
- 함께 검사하는 항목:
  - `source_blocks`가 NEW 인덱스 범위 안에 있는지, 중복되지 않는지
  - 800자 상한을 넘는지
  - 원문의 수치와 고유명사가 빠졌는지(샘플 비교)
- 폴백을 썼는지(`fallback_used`)와 재시도 횟수를 로그와 metadata에 남긴다.

**E4. 영문 섹션 제목 감지 (rule 경로, 계층 분석 입력)**
- `detect_heading`과 `detect_section_level`은 `en`일 때 다음을 제목으로 인식한다.
  - `1 Introduction`(번호 + 대문자로 시작하는 단어)
  - `A.1 …`
  - `Abstract`, `References`, `Acknowledgements`, `Appendix A`
- `arXiv:… [cs.CL] …` 같은 세로 사이드바, 회전된 텍스트, running header는 제목 후보에서 뺀다.

### 2차 (P1): 다국어 QA와 rule 경로 정리

**E5. QA 출력 언어 수정**
- `build_system_prompt`의 언어 지시를 `lang`에 따라 바꾼다. `ko`는 한국어, `en`은 영어로 쓰게 한다.
- `prompts_en.py:60`의 한국어 강제 문구를 고친다.
- 원문 언어와 관계없이 "근거는 컨텍스트 원문"이라는 원칙을 유지한다.
- 이 변경은 생성 결과가 바로 달라지므로 청킹과 별도 커밋으로 낸다.

**E6. 영문 정규화**
- 줄 끝 하이픈을 다음 단어와 붙인다. `pre-trained`처럼 원래 하이픈이 있는 단어는 보호한다.
- 합자(U+FB00~FB06)를 정규화한다.
- `en`에서 줄 단위로 끊긴 블록을 공백으로 병합한다.

**E7. 필터**
- `_is_admin_anchor`는 `en`일 때 한글 비율 대신 영문 완성 문장 유무로 판정한다. 애매하면 남긴다.
- `is_toc_chunk`에 `Contents`와 `Table of Contents`를 추가하고, abstract·참고문헌·캡션이 지워지지 않게 한다.
- rule 병합의 `min_chars`/`max_chars`와 `make_splitter` 구분자는 실제 호출 지점을 확인한 뒤 언어별로 나눈다.

**E8. 카테고리 언어 옵션**
- `ingestion/prompts.py`의 한국어 강제 문구를 `taxonomy_language`(`ko`/`en`/`source`, 기본값 `ko`)로 바꾼다.
- Master Hierarchy 밖의 값을 만들지 않는 제약은 그대로 유지한다. 카테고리 문자열이 태깅 키이기 때문이다.

### 추가 (P1): 표 → 산문 변환의 수치 손실 (2026-11-16 한국어 회귀 확인에서 발견)

근거는 [DEV_261115.md](../History/DEV_261115.md)의 "한국어 회귀 확인" 절이다.
- 보도자료 PDF에서 큰 표가 있는 페이지(9, 11~13쪽)는 숫자의 약 30%가 빠지고, 실행마다 결과 차이도 크다.
- 수치를 잘못 옮긴 사례도 있다(부천과 안산이 같은 값).
- 이번 언어 작업과 관계없는 기존 문제다. 원인은 표 규칙의 "표 내용을 자연스러운 한국어 산문으로 변환"이다.

**E9. 원인 측정 (선행)**
- 표 블록 크기(행 수, 글자 수)별로 숫자 보존율과 잘못 옮긴 수치를 측정한다.
- 대상은 보도자료 PDF 1종과 표가 많은 문서 1~2종이다.
- 실행마다 결과가 달라지므로 3회 이상 돌려 범위로 본다.

**E10. 개선안 (E9 결과로 고른다)**

| 안 | 내용 | 장점 | 단점 |
| --- | --- | --- | --- |
| A. 큰 표 행 단위 분할 | 일정 행 수(예: 10행)를 넘는 표는 머리글 행을 붙여 여러 블록으로 나눈 뒤 LLM에 넘긴다 | 한 번에 변환할 양이 줄어 누락이 줄어든다. 프롬프트 변경이 작다 | 배치와 호출 수가 늘어난다 |
| B. 큰 표는 원문 유지 | 일정 크기를 넘는 표는 LLM 변환 없이 마크다운 그대로 청크로 만든다 | 수치 손실 0 | 산문 기반 QA 생성과 검색 품질에 미치는 영향을 확인해야 한다 |
| C. 변환 후 숫자 대조 | 원문 표의 숫자 집합과 출력 숫자를 비교해, 보존율이 기준 미만이면 다시 요청하거나 원문으로 폴백한다 | A·B와 함께 쓸 수 있다. 잘못 옮긴 값을 검출한다 | 다시 요청하는 비용이 든다. 기준값을 정해야 한다 |

- 권장: A + C. B는 A + C로 부족할 때 고려한다.
- **결과 (2026-11-17):** E9에서 원인이 하나 더 나왔다. 파서가 쌓인 칸을 한 행으로 합치고 있었다(D).
  - D(파서 수정)만 적용하면 숫자 보존 35~44%, D + A는 45~48%였다.
  - D + B로 98~99%를 얻어 B를 채택했다. 700자가 넘는 표는 머리글을 붙인 원문 조각으로 청크를 만든다.
  - C는 B로 대상이 사라져 적용하지 않았다.
  - 상세는 [DEV_261117.md](../History/DEV_261117.md).
- 한국어와 영문 모두에 적용한다. 표 규칙은 두 프롬프트에 공통이다.
- 검증: E9와 같은 문서로 변경 전후 숫자 보존율, 잘못 옮긴 수치 수, 청크 수, LLM 호출 수를 비교한다.

### 3차 (P2): UI와 운영

- Documents 화면에 판별된 문서 언어를 표시하고 수동으로 바꿀 수 있게 한다. QA 언어 설정과 구분해서 설명한다.
- `mixed` 정책(블록 단위 언어 반영)을 추가한다.
- 영문 공백 복원(`_span_text_with_spaces`)을 공백 glyph가 없는 PDF 샘플을 확보한 뒤 구현한다.
- 청크 머리말 라벨을 언어별로 바꾼다.
- 언어별 청크 수, 길이 분포, 청킹 시간, 임베딩 호출 수, 검색 Recall@K를 비교한다.
