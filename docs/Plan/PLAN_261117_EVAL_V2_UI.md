## 1. QA Pipeline — 평가 진행

- 진행 막대를 2개로 줄인다.
  - **데이터 검증:** "76/76 정상 · 중복 의심 2건"
  - **AI 품질 평가:** "41/76 평가 · 통과 37"
- 완료 카드에는 통과율, 등급, 불통과 수(근거·수치 오류), 평가 실패 수를 표시하고 "결과 보기" 버튼을 둔다.
- 평가 모델 설명 문구를 바꾼다. "관련성·근거성·완전성" → "근거성·정확성·완전성·질문 품질".
- 비교 기간에만 "평가 방식: v1(기본) / v2(미리보기)" 선택을 둔다. 기본값을 v2로 바꾸면 없앤다.
- 백엔드 작업 상태의 `layers` 키를 v2에서 `validation`, `judge`로 보낸다. 화면은 받은 키에 따라 막대를 그린다.

## 2. Evaluation — 평가 결과

```
┌ 머리글: 모델 · 문서 · 일시 · [v2] ─────────────────────────────┐
├ 요약 카드: 전체 │ 통과(통과율) │ 등급 │ 근거·수치 오류 · 평가 실패 ──┤
├ 데이터 검증 ─────────────┬ AI 품질 평가 ────────────────────────┤
│ 구문 정상 n/n            │ 지표 4개 막대 + 기준선                │
│ 중복 의심 n건 [보기]      │ 언어 조합 분포(교차 언어가 있을 때만)  │
│ 경고                     │                                     │
│ ▸ 상세: 의도·문서 분포    │                                     │
├ 실패 유형 칩 (누르면 표 필터) ──────────────────────────────────┤
├ 상세 평가 결과: [전체|통과|불통과|평가 실패|제외] 질문·점수·판정·사유·언어 ┤
└────────────────────────────────────────────────────────────────┘
```

- **요약 카드:**
  - 근거·수치 오류(Hard Fail)와 평가 실패는 0이 아닐 때만 강조한다.
  - 등급을 보류하면 등급 칸에 사유를 적는다. 예: "평가 실패 25% — 등급 보류".
- **데이터 검증 카드:**
  - 지금의 "데이터 통계" 레이더 차트를 대체한다. 점수는 없다.
  - 의도 분포 트리맵은 상세 보기 안으로 옮긴다. 차트 코드는 그대로 쓴다.
  - "중복 의심 [보기]"를 누르면 표에 해당 질문 쌍만 나온다.
- **AI 품질 평가 카드:**
  - 지금 `QualityScoreChart`를 지표 4개로 바꾸고 기준선을 표시한다. 근거성·정확성은 0.6, 질문 품질은 0.5다.
  - 언어 조합 분포(`by_language_policy`)는 한→한만 있으면 숨긴다.
- **실패 유형 칩:** `failure_counts`를 많은 순서로 보여 준다. 언어 유형(단위 불일치, 가능성→확정 등)도 같은 줄에 둔다.
- **표:**
  - 판정 칸 값: 통과 / 불통과 / 근거·수치 오류 / 평가 실패 / 제외(구문 탈락).
  - 사유 칸은 `fail_reasons`와 `failure_types`의 첫 항목이다.
  - 교차 언어 QA에는 "영→한" 배지를 단다.
- **QA 상세 보기:**
  - 지표 4개를 보여 준다.
  - 주장별 근거 목록을 보여 준다. 주장과 원문 인용을 나란히 놓고, 판정(근거 일치 / 근거 없음 / 원문과 상충, 2026-11-22 변경)을 색으로 구분한다.
  - 언어 검사 결과를 칩으로 보여 준다.
  - 판정 이유 한 문장을 보여 준다.
  - 원문 언어가 판별값이면 "판별값"이라고 작게 적는다.
- **v1 결과:** 지금 화면을 그대로 쓴다. 머리글에 "v1 평가" 배지만 단다.

## 3. 리포트 — HTML·xlsx 내보내기

리포트는 화면을 보지 않은 사람이 읽는다. 그래서 화면보다 **결론과 근거**를 앞에 둔다.

**HTML (v2)**
1. **머리글:** 생성 모델, 평가 모델, 평가 방식(v2, `judge_version`), 문서, 일시.
2. **결론 한 줄:** 예: "76개 중 68개 통과(89.5%), 등급 A. 근거·수치 오류 3건, 지시어 질문 4건."
3. **요약 카드:** 통과율, 등급, 지표 4개 평균, 근거·수치 오류, 평가 실패.
4. **데이터 검증:** 구문 결과, 중복 의심 쌍 목록, 경고, 의도 분포 차트.
5. **불통과 QA (신규):** 불통과 QA만 먼저 모은다. 각 QA에 질문, 답변, 사유, 문제 주장과 원문 인용을 붙인다. 리포트를 받은 사람이 가장 먼저 볼 부분이다.
6. **전체 QA 표:** 칸은 ID, 의도, 질문, 답변, QA 점수, 판정, 실패 유형, 언어다. 행을 펼치면 지표 4개와 근거가 나온다.
7. **평가 기준 부록:** 가중치, 통과·불통과 기준, 등급 구간, 언어 정책. 점수의 뜻을 리포트 안에서 설명하기 위해서다.

- v1 리포트는 지금 형식을 유지한다. 머리글에 "v1 평가"를 표시한다.
- 인쇄(PDF 저장)할 때 불통과 QA 절은 QA 단위로 페이지가 나뉘지 않게 한다.

**xlsx (v2)**
- **Summary 시트:** 요약과 평가 기준.
- **Validation 시트:** 구문 탈락, 중복 쌍, 경고.
- **Detail 시트:** QA별 지표 4개, QA 점수, 판정, 실패 유형, 언어 정책, 이유.
- **Evidence 시트:** QA ID, 주장, 원문 인용, 판정. 한 행에 주장 하나다.

## 4. Dashboard · 이력

- **모델 비교와 점수 추이:**
  - 같은 평가 버전끼리만 평균을 낸다.
  - 비교 단계에서는 v1만 보인다.
  - 기본값을 v2로 바꾼 뒤에 버전 선택(v2 기본 / v1)을 추가한다.
  - v2에서는 평균 점수 옆에 평균 통과율도 표시한다.
- **이력 목록과 드롭다운:** v2 결과에 작은 배지를 단다. 등급을 보류한 결과는 등급 칸을 "보류"로 표시한다.

## 5. 공통

- **타입:** `types/evaluation.ts`에 v2 결과 타입을 추가한다. 화면은 `eval_version`으로 분기한다. 값이 없으면 v1이다.
- **용어:** 화면과 리포트에서 같은 말을 쓴다.

  | 키 | 표시 |
  | --- | --- |
  | groundedness | 근거성 |
  | correctness | 정확성 |
  | completeness | 완전성 |
  | question_quality | 질문 품질 |
  | hard_fail | 근거·수치 오류 |
  | evaluation_error | 평가 실패 |

- **모바일:**
  - 요약 카드는 2×2로 배치하고, 카드는 세로로 쌓는다.
  - 표는 지금 쓰는 모바일 카드 목록 방식을 그대로 쓴다. 근거 목록은 접어 둔다.
  - 360~430px 폭 E2E(`dashboard-mobile`, 평가 화면)를 다시 실행한다.
- **다크 모드:** 판정 색(통과·불통과·오류·실패)은 지금 상태 색 토큰을 쓴다.
