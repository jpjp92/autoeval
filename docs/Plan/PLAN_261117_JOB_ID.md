# 작업 ID 형식 변경 기획 (2026-11-17)

> 상태: 구현 완료(2026-11-17). 결과는 [DEV_261117.md](../History/DEV_261117.md)의 "작업 ID 형식" 절.

## 1. 문제

- **ID가 단계마다 따로 만들어진다:** QA 생성은 `gen_YYYYMMDD_HHMMSS_ffffff`, 평가는 `eval_…`이다.
- **대시보드에서는 생성 ID만 보인다:** 최근 작업 목록이 생성 결과 기준이라 작업 ID가 모두 `gen_`으로 시작한다. 평가 ID는 응답에 오지만 화면에 나오지 않는다.
- **ID로 묶을 수 없다:** 생성과 그 평가를 ID만으로 연결할 수 없다.

## 2. 형식

```
QA 생성 :  TX-261117-K7M2QD
그 평가 :  TX-261117-K7M2QD-E1   (재평가 -E2, -E3 …)
```

- `TX-YYMMDD-` + 6자리 무작위 문자열이다.
  - 문자는 Crockford Base32에서 0, 1, I, L, O를 뺀 대문자·숫자를 쓴다(헷갈리는 글자 제외).
  - 같은 날 경우의 수는 약 7억이다. 같은 시각에 작업이 몰려도 겹치지 않는다.
- 평가 ID는 생성 ID 뒤에 `-E번호`를 붙인다. 번호는 같은 생성으로 저장된 평가(`job_id LIKE '{생성ID}-E%'`)와 메모리에 있는 평가 작업 중 가장 큰 번호 + 1이다.
- 연결된 생성이 옛 형식(`gen_…`)이거나 찾을 수 없으면 평가에 새 `TX-…`를 붙인다.

## 3. 범위

- 바꾸는 곳: `generation_api.py`, `evaluation_api.py`의 ID 생성. 새 모듈 `backend/job_ids.py`.
- 기존 `gen_…`, `eval_…` 기록은 바꾸지 않는다. 작업 ID 형식에 기대는 코드는 없다(확인함).
- DB 스키마는 바꾸지 않는다.
- 문서 수집 작업 ID(UUID)는 그대로 둔다.
- 대시보드 최근 작업의 ⓘ 상세에 평가 ID 한 줄을 추가한다.

## 4. 검증

- 단위 테스트: 형식, 문자 집합, 평가 번호 매기기(빈 목록, 기존 E1·E3, 다른 생성의 ID 무시, 옛 형식 생성), 무작위 충돌 없음(1만 개).
