# 문서 분석(PDF 추출) 속도 개선 기획 (2026-11-17)

> 상태: 구현 완료(2026-11-17). 결과는 [DEV_261117.md](../History/DEV_261117.md)의 "PDF 추출 속도" 절.

## 1. 문제

- 15쪽 보도자료 PDF 하나가 "문서 분석 중"에서 몇 분 동안 머물렀다.
- 운영 DB 확인(읽기 전용): `doc_metadata` 생성부터 청크 저장까지는 27~28초였다. 나머지 시간은 그 앞의 텍스트 추출에 쓰였다.
- 로컬 프로파일: 추출 시간의 대부분은 PyMuPDF `page.find_tables()`가 쓴다.
  - 9~14쪽에는 쪽마다 그림 요소가 1만 3천~1만 5천 개 있고, 그중 약 97%가 크기 0인 선이다.
  - 이 쪽들은 표 감지에 쪽당 3~4초가 걸린다. 나머지 쪽은 0.1초 이하다.

## 2. 방안

1. **크기 0 그림 요소 제외:** 가로·세로가 모두 0.5pt보다 작은 요소를 빼고 `find_tables(paths=...)`에 넘긴다. 이런 요소는 표 테두리가 될 수 없다.
2. **쪽 단위 병렬:**
   - 쪽 처리 코드를 `_extract_pdf_page`로 분리하고, 프로세스 풀에서 쪽마다 실행한다.
   - 서버는 스레드에서 이 코드를 호출하므로 `spawn` 방식으로 프로세스를 만든다.
   - 프로세스 수는 `PDF_EXTRACT_WORKERS`로 정한다. 설정하지 않으면 1(순차)이다. 서버 코어 수를 확인한 뒤 환경변수로 켠다.
   - 4쪽 미만인 문서는 순차로 처리한다.
   - 병렬 처리가 실패하면 순차로 다시 처리한다.
3. **쪽 단위 진행 표시:** 작업 메시지를 "텍스트·표 추출 중 (n/전체쪽)"으로 보낸다.

검토했지만 뺀 것:
- **선 개수 상한:** 걸러낸 뒤에는 상한을 넘는 쪽이 없어 효과가 없었다.
- **XML 추출:** PDF에는 표 구조가 없어 표를 얻을 수 없다.

## 3. 검증

- **결과 동일성:** 같은 PDF로 기존 코드와 새 코드의 결과(텍스트·블록·표)를 JSON 해시로 비교한다.
- **시간:** 순차와 병렬 두 경우를 잰다.
- **단위 테스트:** `backend/tests/test_pdf_extract.py`(CI에 추가).
- **운영 메모:** 효과는 서버 코어 수에 따라 다르다. 기본값은 순차이므로 2코어 이상 인스턴스에서만 `PDF_EXTRACT_WORKERS`를 2~4로 설정한다. 프로세스마다 PDF를 따로 열기 때문에 메모리도 그만큼 늘어난다.
