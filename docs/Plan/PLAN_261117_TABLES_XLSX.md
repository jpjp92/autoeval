## 1. 현재 상태

- 수집 형식은 PDF, DOCX, TXT, MD다(`extract_text_by_page`). 업로드 화면은 `accept=".pdf,.docx,.doc,.txt,.md"`다.
- `openpyxl` 3.1.5와 `pandas` 3.0.1은 이미 의존성에 있다(`pyproject.toml`). 다만 수집 경로에서는 쓰지 않는다.
- 표 처리:
  - PDF의 쌓인 칸을 행으로 펼친다.
  - 700자가 넘는 표는 머리글을 붙인 원문 청크로 만들고, 그 이하 표는 LLM이 산문으로 바꾼다.
  - 중첩 표는 `[표] … (하위 표)` 블록으로 꺼낸다.
- 남은 일:
  - 실제 문서 확인: 중첩 표, DOCX
  - 표 앞뒤 제목·각주 묶임
  - 표 청크의 검색·평가 영향
  - 분할 기준 700자 검증
  - 3차 UI

## 2. 작업 단위

### T1. 표 제목·각주를 표 청크에 붙이기 (P1, 작음)

- 문제: 큰 표를 LLM 입력에서 빼면, 표 앞 제목과 표 뒤 각주, 다음 절 제목이 한 청크로 묶인다.
  - 예: `붙임 1` 제목 + 누계 각주 + `붙임 2` 제목
- 변경 (`_split_verbatim_tables`):
  - 바로 앞 블록이 짧은 제목(40자 이하 한 줄)이면 LLM 입력에서 빼고 표 제목으로만 쓴다. 지금은 제목으로 쓰면서 LLM에도 넘긴다.
  - 바로 뒤 블록이 각주 형태(`※`, `*`, `-`, `주)`, `자료:`, `Note:`, `Source:`로 시작하고 300자 이하)이면 마지막 표 조각 끝에 붙이고 LLM 입력에서 뺀다.
  - 각주를 붙여서 800자가 넘으면 붙이지 않는다.
- 검증: 보도자료 PDF에서 표 앞뒤 블록의 귀속을 확인하고, 숫자 보존 98% 이상을 유지한다. 단위 테스트를 추가한다.

### X1. xlsx 수집 (P0, 신규)

엑셀은 내용 전체가 표다. 그래서 LLM 산문화를 거치지 않고, 앞서 만든 원문 표 청크 경로를 그대로 쓴다.

**파싱** (`parsers.extract_text_by_page`에 `xlsx`, `xlsm` 분기 추가, openpyxl):
- 값 읽기:
  - `load_workbook(read_only=False, data_only=True)`로 연다. 수식 칸은 저장된 계산값을 쓴다.
  - 계산값이 없는 파일(엑셀에서 한 번도 계산하지 않은 파일)은 수식 칸이 비어 나온다. 이 경우 경고 로그를 남긴다.
- 시트 처리:
  - 시트 하나를 `page` 하나로 본다(`page` = 시트 순서, 시트 이름은 블록에 기록).
  - 숨김 시트는 건너뛴다. 숨김 행과 열은 1차에서 그대로 포함한다.
- 표 영역 찾기:
  - 빈 행이 2줄 이상 이어지거나 빈 열로 구분되는 덩어리를 각각 하나의 표로 본다.
  - 덩어리마다 첫 번째로 값이 있는 행을 머리글로 본다.
  - 칸이 1~2개뿐인 덩어리(시트 제목, 단위 표기)는 표가 아니라 다음 표의 제목으로 쓴다.
- 병합 칸: 병합 범위 전체에 왼쪽 위 칸의 값을 채운다. 2단 머리글을 위해서다.
- 값 표시:
  - `number_format`에 맞춰 문자열로 바꾼다. 예: 0.123 + `0.0%` → `12.3%`, 날짜 → `2025-11-17`, 천 단위 구분 쉼표 유지
  - 원래 숫자가 바뀌지 않게 하는 것이 핵심이다.
- 출력 형식: PDF 표와 같은 `[표] 시트명 · 제목` + 머리글 + 구분선 + 행.
- 크기 상한:
  - 시트당 2,000행, 문서당 20,000행까지만 읽는다.
  - 넘으면 잘라내고, 몇 행을 잘랐는지 업로드 상태 메시지에 남긴다. 임베딩 호출 수와 비용을 막기 위해서다.
  - 기준값은 사용자가 정한다(4장).

**청킹**:
- `chunking_method`와 관계없이 xlsx는 LLM 청킹을 하지 않는다. 모든 표를 `split_large_table_text`로 나눠 원문 표 청크로 만든다. 700자 이하 표는 조각 하나가 된다.
- 표 조각마다 머리글 행을 반복한다(기존 기능).
- 언어 판별(`detect_language`)은 칸 글자로 그대로 한다.

**API·화면**:
- 업로드 화면 `accept`에 `.xlsx`를 추가한다. `.xlsm`은 매크로를 실행하지 않고 값만 읽으므로 함께 받는다.
- `.xls`(구형식)는 openpyxl이 읽지 못한다. 1차에서 제외하고, 업로드하면 안내 메시지를 보여 준다.
- 백엔드 검증: 추출 글자 수 하한(100자)은 기존 비PDF 규칙을 그대로 쓴다.

**이후 단계 (변경 없이 동작해야 하는 것)**:
- 계층 분석, 태깅, QA 생성, 평가는 청크만 보므로 그대로 동작해야 한다.
- 표 청크로 QA를 생성하면 수치가 정확했다(DEV_261117). xlsx에서도 같은지 확인한다.

**검증**:
- 테스트 xlsx는 openpyxl로 만든다. 단위 테스트 항목:
  - 시트 여러 개, 숨김 시트
  - 병합 머리글
  - 빈 행으로 나뉜 표 2개
  - 수식 칸
  - 퍼센트·날짜·쉼표 서식
  - 큰 시트(행 상한)
  - 빈 시트
- 실제 업무 xlsx 1~2개로 업로드부터 QA·평가까지 진행한다. 샘플은 사용자가 제공한다.

### T2. 표 청크의 검색·평가 영향 측정 (P1)

- 질문: 마크다운 표 청크가 산문 청크보다 검색에 불리한가? RAG 평가 점수는 달라지는가?
- 방법 (DB에 쓰지 않는 로컬 측정):
  1. 보도자료 PDF와 xlsx 샘플로 두 가지 청크 세트를 만든다.
     - A: 이전 방식, 표를 산문으로
     - B: 현재 방식, 원문 표 청크
  2. 각 세트를 Gemini Embedding 2로 임베딩해 메모리에 둔다.
  3. 수치를 묻는 질문 20~30개를 만든다(정답 수치와 정답 청크를 함께 기록).
  4. Recall@1/3/5를 비교하고, 상위 청크로 답했을 때 수치 정답률도 비교한다.
- 결과에 따라 처리:
  - B가 검색에서 뒤지면, 표 청크 임베딩 입력에 한 줄 요약을 덧붙이는 방안을 검토한다. 예: `시도별 매매가격 변동률: 전국, 수도권, 서울 … (11.10~11.17)`
  - 이 방안은 저장하는 원문을 바꾸지 않고 임베딩 입력만 바꾼다.

### T3. 분할 기준 700자 검증 (P2)

- T2 측정 때 400 / 700 / 1,000자 세 값을 함께 비교한다.
- 기준: 검색 Recall과 청크 수(임베딩 비용).

### T4. 실제 문서 확인 (사용자 샘플 필요)

- 중첩 표가 있는 DOCX·PDF, 일반 DOCX, xlsx 각 1개 이상.
- 확인 항목:
  - 하위 표 추출, 레이아웃 틀 오판
  - DOCX 큰 표 분할
  - 언어 판별
  - 업로드부터 평가까지 끝까지 진행

### U1. 3차 UI (P2)

- QA 생성 화면에 출력 언어 선택(한국어/English)을 둔다. 값은 기존 `lang` 필드로 보낸다.
- 업로드 완료 카드에 문서 언어 배지를 단다.
  - `IngestionStatusResponse`에 선택 필드 `source_language`를 추가한다.
  - xlsx는 시트 수와 잘린 행 수도 표시한다.
- 계층 분석 버튼 옆에 카테고리 언어 선택(한국어/English/원문 따름)을 둔다. 재분석 시 기존 카테고리와 언어가 섞일 수 있다는 안내를 붙인다.
- 모바일 E2E(360~430px 겹침 검사)를 다시 실행한다.

## 4. 결정이 필요한 것

| 항목 | 제안 기본값 | 비고 |
| --- | --- | --- |
| xlsx 행 상한 | 시트당 2,000행, 문서당 20,000행 | 1만 행 시트 하나면 청크가 약 1,000개 생긴다 |
| `.xls` 구형식 | 1차 제외 | 지원하려면 `xlrd`를 추가해야 한다 |
| `.csv` | 함께 지원 | 시트 하나짜리 표로 같은 경로를 쓴다. 인코딩(UTF-8, CP949)은 자동 판별 |
| 숨김 행·열 | 포함 | 제외하면 데이터가 빠질 수 있다 |
| 수식 계산값 없음 | 경고 후 빈칸 | openpyxl은 수식을 계산하지 않는다 |

## 5. 제약

- DB 스키마와 임베딩 모델은 바꾸지 않는다. 시트 이름 등은 청크 metadata(JSON)에 넣는다.
- 기존 PDF·DOCX 결과는 T1 범위(표 앞뒤 블록 귀속) 밖에서 바뀌지 않아야 한다. 샘플 해시로 확인한다.
- 커밋, 푸시, 배포는 사용자가 요청할 때만 한다.
