## 변경 내용

### Settings 토글 (F1)

- 모바일 헤더의 Settings 버튼이 토글로 동작한다. 일반 탭에서 누르면 Settings로, Settings에서 누르면 직전 일반 탭으로 돌아간다.
- `App.tsx`에 `lastMainTab`을 두고, Settings가 아닌 탭으로 이동할 때만 갱신한다. 복귀 대상이 `settings`가 될 수 없어 연타에도 꼬이지 않는다.
- Settings에서 하단 탭을 고르면 그 탭으로 이동하고, 이후 복귀 대상도 그 탭이 된다.
- Settings 화면에서는 버튼이 `ArrowLeft` 아이콘과 "이전 화면으로 돌아가기", 평소에는 톱니와 "설정 열기"(`aria-label`, `title`).
- 모든 화면 전환(Sidebar, 하단 탭바, 헤더 버튼, 대시보드·평가 이동)이 `navigate()` 하나를 거친다. 데스크톱 Sidebar 동작은 같다.

### 탭별 스크롤 위치 (F2)

- 이전에는 모든 탭이 `main` 스크롤 하나를 같이 써서, 탭을 오가면 직전 탭의 위치가 남았다.
- 전환 직전 `main.scrollTop`을 탭별로 저장하고, 전환 후 `useLayoutEffect`에서 복원한다. 처음 여는 탭은 맨 위.

### 브라우저 뒤로 가기 (F3, 방식 b)

- Settings에 들어갈 때만 `history.pushState`로 기록을 하나 남긴다. 뒤로 가기를 누르면 Settings가 닫히고 복귀 대상 탭으로 간다.
- 헤더 버튼이나 하단 탭으로 Settings를 나갈 때는 `history.back()`으로 그 기록을 지운 뒤 `popstate`에서 목표 탭을 적용한다. 기록이 쌓이지 않는다.
- 일반 탭 사이 전환은 기록하지 않는다. 일반 탭에서 뒤로 가기는 이전처럼 앱을 떠난다.

### 청크 샘플 수 입력 (F4)

- `QAGenerationPanel`의 입력칸 초깃값을 `String(formValues.samples)`로 맞췄다. 이전에는 빈칸으로 보이지만 실제 값은 2였다.

### Dashboard 파이프라인 로그·생성 모델 성능 비교 (F5)

iPhone 화면에서 로그 표의 모델 배지·QA 수·등급이 겹치고, 성능 비교 카드에서 긴 모델 ID가 Best·테스트 횟수와 충돌했다.

- 파이프라인 로그: `lg` 미만은 표 대신 2행 카드다. 1행은 문서명과 평가 등급, 2행은 모델 표시명과 `n QA · 상대 시간`.
  문서명과 모델명은 한 줄 말줄임. 정렬은 select와 오름/내림 버튼으로 하고, 페이지 이동은 표와 같은 데이터를 쓴다.
  ⓘ 버튼을 누르면 작업 ID, 모델 ID, 문서명 전체가 카드 아래에 펼쳐진다. 카드 본문 탭은 평가 상세로 이동한다(ⓘ는 이동하지 않음).
- 데스크톱 표는 그대로다. 모델 배지 최대폭을 `max-w-full`로 바꿔 열 밖으로 나가지 않는다.
- 생성 모델 성능 비교: 모바일은 1행 순위 + 모델명, 2행 Best + `n회 테스트`. `sm` 이상은 이전처럼 한 줄.
  집계값과 순위는 바꾸지 않았다. 표본 수 차이(예: 12회 vs 1회)가 보이도록 테스트 횟수를 항상 표시한다.
- 모델 표시명 `modelLabel()`(`lib/models.ts`): 선택 목록 라벨을 우선 쓰고, 없으면 날짜 접미사를 떼고 정리한다.
  `gpt-5.2-2025-12-11` → GPT-5.2, `gemini-3-flash-preview` → Gemini 3 Flash Preview, `claude-sonnet-4-6` → Claude Sonnet 4.6.
  원래 ID는 데이터 키와 `title`, ⓘ 상세에 그대로 남는다. 데스크톱 표와 성능 비교에도 같은 표시명을 쓴다.
- 두 영역에 중복되던 모델 브랜드 색상 분기를 `modelColors()`로, 등급 배지를 `GradeBadge`로 합쳤다.
- 모바일 페이지 이동 버튼 터치 영역을 키우고(`p-3`), 카드 패딩을 `p-4`로 줄였다.
