# 모바일 UI 개선 기록 (2026-11-12)

기획: [PLAN_261112_MOBILE_UI.md](../Plan/PLAN_261112_MOBILE_UI.md). 브랜치 `dev`.

## 배경

iPhone Safari(375px)에서 카드 본문에 남는 폭이 약 159px이었다.
접힌 사이드바 84px, StepCard 세로 타임라인 52px, 카드 패딩 48px, main 패딩 32px가 폭을 차지했다.
이 때문에 글자가 한두 글자씩 줄바꿈되고, 버튼과 지표, 분류 미리보기가 화면 밖으로 밀렸다.
이번 작업 후 카드 본문 폭은 약 311px이다(375 − main 24 − 카드 패딩 32 − 테두리).

모든 변경은 `lg`(1024px) 미만에만 적용했다. 1024px 이상 데스크톱 레이아웃은 그대로다.

## 변경 내용

### App Shell과 하단 탭바

- `lg` 미만에서 Sidebar를 숨기고 하단 탭바 `MobileTabBar`를 표시한다.
  탭은 Dashboard / Documents / QA Pipeline / Evaluation 4개이고, 터치 영역은 48px이다.
- 햄버거 드로어와 비교한 샘플을 보고 하단 탭바로 결정했다. 화면 간 이동이 잦고 메뉴가 4개라서다.
- Settings는 헤더의 톱니 버튼으로 옮겼다(`lg` 미만에서만 표시). 테마 전환은 기존처럼 알림 패널 하단에 있다.
- 루트 높이를 `h-screen`에서 `h-dvh`로 바꾸고 콘텐츠 영역에 `min-w-0`을 추가했다.
- `app/layout.tsx`에 `viewport` export(`viewportFit: 'cover'`)를 추가했다.
  이전에는 safe-area 값이 0이라 iOS 하단 툴바와 겹쳤다. 탭바 하단에 `env(safe-area-inset-bottom)` 여백을 둔다.
- 알림 패널은 모바일에서 헤더 전체 폭에 맞춰 열린다. 이전에는 `w-80`이 왼쪽으로 잘렸다.
- 탭은 기존처럼 `hidden`으로 항상 마운트되므로, 이동해도 진행 중 작업과 입력값이 유지된다.
- `next.config.ts`에 `devIndicators: false`를 추가했다. 개발 모드의 Next.js 배지가 탭바 왼쪽(Dashboard)을 가렸다.
  오류 오버레이는 그대로 표시된다.

### 공용 StepCard

- `QAGenerationPanel.tsx`와 `DataStandardizationPanel.tsx`에 따로 있던 StepCard를
  `components/common/StepCard.tsx` 하나로 합쳤다.
- 두 사본의 차이는 prop으로 남겼다. QA Pipeline은 모델 드롭다운 때문에 `overflow-visible`,
  Documents는 `clip`(`overflow-hidden`)을 쓴다.
- 비활성 단계의 헤더 배경은 Documents 방식(활성 단계만 진하게)으로 통일했다.
  QA Pipeline 데스크톱에서 대기·완료 단계 헤더가 아주 약간 옅어진다.
- 모바일: 세로 타임라인을 숨기고 카드 헤더에 단계 번호 배지를 표시한다. 패딩은 `p-4`.

### Documents

- 파일명과 "컨텍스트 분석" 버튼, "QA 생성으로 이동" 행을 모바일에서 세로로 쌓는다. 버튼은 전체 폭.
- 분류 미리보기의 H1 › H2 › H3 배지를 본문 아래로 내리고 줄바꿈되게 했다.
- 계층 트리의 들여쓰기를 줄이고, 라벨은 `word-break: keep-all`로 한글 단어 단위로 줄바꿈한다.
  공백 없는 긴 영문은 `overflow-wrap: anywhere`로 넘침을 막는다.
- 카테고리 분석 진행 메시지가 한 줄을 넘으면 줄바꿈된다.

### QA Pipeline

- 공통 버튼(`btnBase`)은 모바일에서 전체 폭, `sm` 이상에서만 최소폭 148px.
- 진행률 행(메시지·퍼센트·취소 버튼)과 대기 행을 모바일에서 세로로 배치했다.
- 카테고리 범위(H1/H2/H3) 선택을 모바일 1열로, 평가 결과 지표 6개를 2열로 바꿨다.
- QA 미리보기 답변은 모바일에서 4줄까지 보이고 "더보기"로 펼친다. 데스크톱은 전체 표시.

### Evaluation

- KPI 4개를 모바일 2열(이전 1열)로 배치하고, 카드 안에서 아이콘을 위로 올렸다.
- 상세 평가 결과: `md`(768px) 미만에서는 표 대신 카드 목록을 보여 준다.
  카드에는 번호, 의도, 성공/보류/실패, 실패 유형, 질문 2줄, 품질·Triad 점수를 표시하고, 탭하면 기존 상세 화면으로 간다.
- History 메뉴는 버튼 위치에 맞춰 왼쪽 또는 오른쪽에 붙어 열린다(`mobileAlign` prop).
  빈 화면에서는 버튼이 오른쪽, 리포트 화면에서는 왼쪽에 있다. Export 메뉴도 화면 안에서 열린다.
- 정보(ⓘ) 툴팁은 hover 전용이라 모바일에서 열 수 없었고, 왼쪽 열 카드에서는 화면 밖으로 나갔다.
  버튼으로 바꿔 탭으로 열리고, 열릴 때 화면 안으로 위치를 보정한다. Escape나 바깥 탭으로 닫힌다.
  데스크톱은 기존처럼 hover로 열린다.
- 페이지 이동 버튼의 터치 영역을 키웠다.

## 테스트

`@playwright/test` 1.64.1을 devDependency로 추가하고 `npm run test:e2e`로 실행한다.
설정은 `frontend/playwright.config.ts`, 테스트는 `frontend/tests/e2e/mobile-layout.spec.ts`.
실행 중인 앱(기본 `http://localhost:3000`, `E2E_BASE_URL`로 변경 가능)을 대상으로 한다.

| 너비 | 검사 |
| --- | --- |
| 360 / 375 / 390 / 430px | 탭바 표시, 탭 4개 전환과 터치 영역 44px 이상, 탭별 가로 넘침 없음 |
| 〃 | 알림 패널이 화면 안에 있음 |
| 〃 | 히스토리에서 평가 리포트를 열고 History 메뉴, KPI 툴팁(탭), 리포트, QA 상세 화면의 가로 넘침 없음 |
| 1024 / 1440px | Sidebar 유지, 탭바 숨김, 탭별 가로 넘침 없음 |

가로 넘침은 문서 `scrollWidth`와 함께, 화면 밖으로 나간 요소를 개별로 찾는다.
가로 스크롤 컨테이너 안의 요소와 `aria-hidden` 장식 요소만 제외한다.

WSL에는 브라우저 실행용 시스템 라이브러리가 없어(설치에 sudo 필요) Playwright 공식 이미지로 실행했다.

```bash
cd frontend
docker run --rm --network host --ipc=host -u $(id -u):$(id -g) -e HOME=/tmp \
  -v $PWD:/work -w /work mcr.microsoft.com/playwright:v1.64.1-noble \
  npx playwright test --workers=2
```

결과 (Docker 개발 환경, 로컬 DB의 평가 히스토리 50건 사용):

- Playwright 14개 통과
- `npx tsc --noEmit` 통과
- `npm run test:proxy` 2개 통과
- `next build --webpack` 성공

개발 서버는 병렬 실행 시 첫 컴파일이 느려 4 workers에서 타임아웃이 났다. `--workers=2`를 권장한다.

## 확인하지 못한 것

- iPhone Safari 실기기 확인(safe-area, 주소창 높이 변화)은 아직이다.
- QA 생성·평가가 실제로 진행 중인 화면(진행률, QA 미리보기, 평가 결과 지표)은 LLM 호출이 필요해 자동 검사에 넣지 않았다.
  레이아웃 코드만 수정했다.
- 데이터가 있는 Documents 화면(분류 미리보기, 계층 트리)도 같은 이유로 실제 데이터로 보지 못했다.
- 라이트 테마는 자동 검사에 포함하지 않았다.

## 남은 일

- 1023px 이하 글꼴 축소(`index.css`, 11~14px)는 그대로 두었다. 실기기에서 보고 축소 폭을 줄일지 정한다.
- 768~1023px 태블릿은 하단 탭바 + 데스크톱형 2열 레이아웃이 섞인다. 실제 기기에서 확인이 필요하다.
- 기존 버그(이번 작업과 무관): QA Pipeline의 "청크 샘플 수" 입력이 처음에 빈칸으로 보이지만 실제 값은 2다
  (`sampleInputValue` 초깃값 `""`, `formValues.samples` 초깃값 2).
- Docker 개발 컨테이너가 root로 실행되어 `frontend/next-env.d.ts`를 root 소유로 다시 만든다.
  호스트에서 `next build`를 하려면 이 파일을 지우고 실행해야 했다.
