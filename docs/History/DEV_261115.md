# 영문 문서 원문 보존 1차 기록 (2026-11-15)

기획: [PLAN_261115_ENGLISH_CHUNKING.md](../Plan/PLAN_261115_ENGLISH_CHUNKING.md)의 1차(P0, E1~E4). 브랜치 `dev`.
한국어 문서 경로는 바꾸지 않았다. 바뀐 것은 LLM 프롬프트에 추가한 "원문 언어 유지" 한 줄뿐이다.

## 변경 내용

### 언어 판별 (E1)

- 새 모듈 `ingestion/language.py`의 `detect_language(texts)`를 추가했다. 반환값은 `{language, hangul_ratio, letters}`다.
  - 한글/(한글+라틴) 비율이 0.05 미만이고 글자 수가 200자 이상이면 `en`, 나머지는 `ko`로 판정한다.
  - 기준을 넘지 못하거나 글자 수가 적으면 기존 동작인 `ko`로 둔다.
  - 한국어 문서에 영문 용어가 섞여 있어도 `ko`다.
- `pipeline.py`에서 블록을 추출한 직후 한 번 판별하고, 결과를 로그로 남긴다(`Source language: en (hangul_ratio=…)`).
- 청크 metadata(JSON)에 다음 값을 기록한다. DB 스키마는 바꾸지 않았다.
  - `source_language`
  - `chunk_policy`(`ko-v1` / `en-v1`)
  - `fallback_reason`(폴백한 청크만)

### 영문 LLM 청킹 프롬프트 (E2)

- `llm_chunker.py`에 영문 프롬프트를 추가했다: `SYSTEM_PROMPT_EN`(PDF), `DOCX_SYSTEM_PROMPT_EN`, `USER_TEMPLATE_EN`.
  - `select_prompts(language, docx)`가 언어에 맞는 프롬프트를 고른다.
- 영문 프롬프트의 최우선 규칙은 `<language_rules>`다.
  - 번역하지 않는다.
  - 수치·단위·인용·고유명사·URL·코드를 그대로 보존한다.
  - 노이즈만 고치고 요약하거나 내용을 빼지 않는다.
- 영문 프롬프트의 나머지 규칙:
  - 노이즈 교정: 줄 끝 하이픈과 합자를 정리하고, `arXiv:… [cs.CL]` 사이드바 스탬프를 지운다.
  - 영문 제목은 다음 청크의 첫 줄로 붙인다.
  - 청크가 연결어(`However`, `Therefore` 등)로 끝나지 않게 한다.
  - 표는 영문 산문으로 바꾸되 행과 열의 관계를 보존한다.
  - `section_title`은 영문으로 쓴다.
- 기존 입출력 규약은 그대로다: CTX/NEW 블록, JSON 배열, 200~800자, `[표]` 마커.
  - `[표]`는 파서가 넣는 구조 표식이라 영문 문서에서도 그대로 둔다.
- 한국어 PDF·DOCX 프롬프트에는 `<role>`에 "원문 언어를 유지하세요. 영문 용어·인용·문장은 번역하지 말고 원문 그대로 둡니다." 한 줄만 추가했다.

### LLM 출력 사후 검증 (E3)

- `find_translated_chunks()`는 원문 블록이 영문(한글 비율 0.05 미만)인 청크만 검사한다. `[표]` 마커는 계산에서 뺀다.
  - 출력 `text`나 `section_title`의 한글 비율이 원문보다 0.05 이상 높으면 번역으로 본다.
- `_process_batch()`는 `en` 배치에서 번역이 감지되면 한 번 다시 요청한다.
  - 그래도 번역되면 원문 블록으로 폴백하고 `fallback_reason="translated"`를 남긴다.
  - 재시도 횟수는 `llm_retries`로 남긴다.
- 기존 폴백에도 사유를 붙였다: JSON 파싱 실패는 `json_parse`, 호출 오류는 `error`.
  - 폴백 청크 수는 청킹 완료 로그에 함께 찍는다.
  - 429(quota) 오류는 기존처럼 즉시 중단한다.

### 영문 섹션 제목 감지 (E4, rule 경로)

- `detect_heading`, `detect_section_level`, `build_sections`에 `language` 인자를 추가했다. 기본값은 `"ko"`이고, `ko`일 때는 기존 규칙만 쓴다.
- `en`에서 제목으로 인식하는 것:
  - 번호 제목: `1 Introduction`(레벨 1), `3.1 …`(레벨 2), `3.2.1 …`(레벨 3), `A.2 …`
  - `Appendix A`
  - 이름 제목: `Abstract`, `References`, `Conclusion` 등
- 제목으로 보지 않는 것:
  - 마침표나 쉼표로 끝나는 줄
  - 13단어 이상인 줄
  - `arXiv:… [cs.CL]` 같은 사이드바 스탬프
- `ingest_with_rule_chunking`, `ingest_with_llm_chunking`에 `language` 인자를 추가했다. 청크에는 `source_language`가 실린다.

## 2차 (P1, E5~E8)

### QA 출력 언어 (E5)

- 이전에는 `lang=en`이어도 QA가 한국어로 나왔다.
  - 실제 실행 경로인 `build_system_prompt`(`worker.py:382`)가 `lang`을 받기만 하고 쓰지 않았다.
  - 정적 프롬프트 `prompts_en.py`도 한국어 출력을 지시했다.
- `build_system_prompt`는 `lang == "en"`일 때만 `<output_language>` 블록을 덧붙인다.
  - 블록 내용: 영어로 작성하고, 한국어 어미 규칙은 적용하지 않으며, 수치·인용·용어는 원문대로 둔다.
  - `ko` 프롬프트는 이전과 같다.
- `prompts_en.py`의 언어·어투 지시를 영어로 바꿨다.
- 실측(BERT의 영문 청크 1개, `gemini-3.8-flash`):

  | | 적응형 프롬프트 | 정적 프롬프트 |
  | --- | --- | --- |
  | `lang=ko` | 한국어 QA 3개 | 한국어 QA 3개 |
  | `lang=en` | 영어 QA 3개, 한글 0 | 영어 QA 3개, 한글 0 |

- QA 생성 화면에는 언어 선택이 없다(`lang: "ko"` 고정). 선택 UI는 3차에서 다룬다.

### 영문 정규화 (E6)

- `language.py`에 `normalize_english_blocks()`를 추가했다. 파이프라인은 `en` 문서일 때만 청킹 전에 블록 text에 적용한다. LLM·rule 두 경로 모두 해당된다.
- 합자: U+FB00~FB06(`ﬁ`, `ﬂ` 등)을 풀어 쓴다.
- 줄바꿈 하이픈(`addi- tional`, 하이픈 뒤에 공백이나 줄바꿈이 있는 경우)은 문서 전체 단어 빈도로 처리를 정한다.
  - 판단 순서:
    1. 붙인 형태가 더 많이 나오면 붙인다.
    2. 하이픈 형태가 문서에 있으면 하이픈을 유지한다.
    3. 3자 이상인 두 조각이 모두 단독 단어로 나오면 하이픈을 유지한다.
    4. 나머지는 붙인다.
  - `fine-tune`처럼 하이픈 뒤에 공백이 없는 단어는 건드리지 않는다.
  - 빈도를 셀 때 줄바꿈 조각(`com- bined`의 `com`)은 단어로 치지 않는다.
- 실측(rule 경로):
  - 하이픈 줄바꿈: Attention 11 → 0, BERT 253 → 0
  - 합자: BERT 157 → 0
  - 잘못 붙인 경우는 약 300개 중 3개다(`sequencealigned`, `Englishto`, `Multigranularity`). 사전 없이 규칙만으로는 더 줄이지 못했다.

### 필터 (E7)

- `_is_admin_anchor(content, language="ko")`: `en`일 때는 한글 비율을 보지 않는다.
  - 영문 완성 문장도 없고 3자 이상 단어도 없는 날짜·번호 나열만 메타로 판정한다.
  - 제목과 지표 나열(`Accuracy: 94.2%`)은 남긴다.
- `/analyze-hierarchy`는 샘플 청크의 언어를 판별해 이 함수에 넘긴다.
  - 실측(BERT 샘플 37개): 기존 규칙으로는 18개가 메타로 빠졌다. 10개 이상이 남아 필터가 실제로 적용되던 상황이다. 새 규칙에서는 0개다.
  - 1차 기록에서 "영향이 작다"고 본 판단은 틀렸다.
- `is_toc_chunk(text, language="ko")`: `en`일 때 다음을 바꿨다.
  - 목차 키워드에 `Contents`와 `Table of Contents`를 더했다.
  - "완성 문장이 거의 없으면 목차" 판정에서 문장 수를 영문 문장으로 센다.
  - 청커의 세 군데 호출에 언어를 넘긴다. 파서 단계의 페이지 판정(언어 판별 전)은 `ko` 그대로다.

### 카테고리 언어 옵션 (E8)

- `build_hierarchy_prompt(…, taxonomy_language="ko")`: `en`이면 영문 프롬프트를 쓴다.
  - 카테고리 개수 규칙은 같고, 이름은 4단어 이하의 Title Case로 쓴다. domain profile도 영문으로 나온다.
  - `ko` 프롬프트는 HEAD와 문자열이 같다.
- `POST /analyze-hierarchy` 요청에 선택 필드 `taxonomy_language`(`ko` / `en` / `source`)를 추가했다. 기본값은 `ko`이고, `source`는 샘플의 문서 언어를 따른다.
  - 기존 요청은 그대로 동작한다.
  - 태깅은 Master Hierarchy에서 고르기만 하므로 바꾸지 않았다.
- 실측(BERT, `en`):
  - H1: `Model Architecture`, `Pre-training Objectives`, `Training and Fine-tuning`, `Evaluation and Performance`, `Related Work`
  - domain profile `NLP Research`, 한글 0
